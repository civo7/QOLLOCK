# QOLLOCK visual surface inventory

Source snapshot: 2026-10-06, including the expanded Customize catalog.
This inventories independent visual surfaces and the children whose appearance
QOLLOCK changes. Anonymous repeated native rows/icons are grouped by their actual
owner; this is not an inventory of every native game panel. Source changes during
the same session can move the cited line numbers.

Verification is offline: active XML includes, manifest registration, current
owners, and CSS selectors. A selector used by source is not proof that every game
state creates it. Conditional native panels must be retained. Native geometry,
hit testing, transitions, and persistence still need maintainer compilation/repack
and client acceptance. The simulator is not client acceptance.

## Reading the matrix

`C` = `Hud/.HudCore`; `G` = `C/gameplay_hud`; `A` = `C/AbilitiesContainer`;
`L` = `C/StatsAndModsContainer/LowerLeft`; `X` =
`G/gameplay_hud_alive/crosshair`. A class is written `.class`; a slash denotes
the owner's scoped path, not a guarantee of direct ancestry for fallback lookups.
`R/U` means increasing X moves right and increasing Y moves up. Pixels are
Panorama layout pixels, not automatically physical display pixels. Scale `%`
has nominal 100; factor has nominal 1. Opacity is 0..1 unless noted.
`PREFIX_{A,B}` expands to two exact keys. No geometry/color column means the
surface has no independent persisted control of that kind. Palette keys retain
their old meanings; supported owners also accept [tagged RGB](core/custom_colors.md).
A mode/toggle is still a useful editor
control even when dragging is unavailable.

## Settings coverage and implementation order

The current settings context loads metadata, renderer and UI modules, not feature
manifests. Manifest declaration therefore does **not** prove that a key has a
rendered settings control. The following read-only probe compares exact manifest
`key:` literals against metadata and established pane/controls sources; it is a
triage check, not a complete renderer/schema proof:

```powershell
@'
const fs = require('fs');
const root = 'panorama/scripts';
const files = ['ui/ql_settings_metadata.js','ui/gameplay_tabs.js','ui/config_tab.js',
  'ui/audio.js','ui/arcade_tab.js','ui/dev_tab.js','ui/controls.js','ui/ql_settings_tabs.js'];
const ui = files.map(f => fs.readFileSync(root+'/'+f, 'utf8')).join('\n');
for (const name of fs.readdirSync(root+'/manifests')) {
  const source = fs.readFileSync(root+'/manifests/'+name+'/manifest.js', 'utf8');
  const keys = [...source.matchAll(/key:\s*["']([A-Z][A-Z0-9_]*)["']/g)].map(m => m[1]);
  const missing = keys.filter(k => !new RegExp('\\b'+k+'\\b').test(ui));
  if (missing.length) console.log(name+': '+missing.join(', '));
}
'@ | node
```

At inventory time it reported:

- `AMMO_PANEL_SCALE`: active runtime key without an exact occurrence in those UI sources.
- `ENABLE_STAT_BONUSES`, `STAT_BONUSES_SCALE`, `STAT_BONUSES_X_OFFSET`,
  `STAT_BONUSES_Y_OFFSET`: active overlay family without exact UI occurrences.
- `ENABLE_BETTER_UNSECURED_SHOW_ICON_TEXT`,
  `ENABLE_ENEMY_COLORED_HEALTHBAR`, `ENABLE_ALLY_COLORED_HEALTHBAR`,
  `ENABLE_ONE_TIME`: mode/master/compatibility mappings must be examined before
  calling these missing switches bugs.
- `MINIMAP_LARGE_SIZE`, `ENABLE_MIN_SOULS`, `ENABLE_UNSPENT_SOULS`:
  compatibility/inactive entries, not recommendations to activate functionality.

`ENABLE_CHAT` is a shared HUD key outside the chat-images manifest's settings.
The old HUD check for `ENABLE_COLOR_WARNING` referenced a nonexistent setting;
the current owner uses the actual colored-healthbar master and threshold keys.
Do not expose that nonexistent key as an editor control. Customize now exposes
the ammo-scale alias and stat-bonus family missed by this established-pane probe.
`tests/customize_catalog.test.js` validates current visual manifest coverage,
every inspector, defaults, config
normalization, current compact schema, actual inspector renderer and owner
cleanup. Lexical presence alone proves none of those contracts.

Recommended implementation sequence:

1. Catalog every active surface with its existing toggles/modes, including rows
   without drag. Keep special-context/static/inactive content explicitly marked.
2. Enable geometry only for owners with verified position keys. Better-unsecured
   uses down-positive Y. Passive margins retain percentage entry; dragging is
   blocked until their native containing-block dimensions are verified. Keep
   shared-key dependencies visible (purchase popups, compass speed, minimap
   children, healthbar descendants).
3. Expose only existing palette/size/opacity semantics. Fixed warning colors,
   target/world-bound markers, and illustrative previews cannot become generic
   RGB/drag controls without a new authorized settings contract.
4. Capture missing native states: failed cast, ability buffs including fire-rate,
   ally/enemy health warnings, death/report, shop/quickbuy, objectives, hero-specific
   resources/modifiers, profile/players/friends, pause/testing/aspect transitions.
   State exactly which scoped parent and IDs are needed; do not prune a feature
   because a single dump misses it.
5. Maintainer client acceptance after compile/repack: dragging across UI-scale and
   aspect ratios, conditional surfaces appearing after an editor session starts,
   panel replacement, Apply/Cancel restoration, native animation feedback,
   Alt/Tab map modes, scoreboard/shop/respawn/hideout and restart durability.

The inventory adds no defaults or runtime behavior. Its catalog coverage does
not establish native acceptance.
